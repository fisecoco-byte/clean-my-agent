# 扫描性能

交互式工作树 / 依赖页先发现目录，再在后台完成空间、引用、运行状态和活跃度检查。首次发现目录前显示 loading 动画和耗时，隐藏空表格与零计数；发现结果后才切换到列表。列表提前可见不代表测量已完成；完整检查结束前不开放清理。JSON、文本、MCP 和指定路径操作仍等待完整结果。

## Rust 0.4.0

当前运行时使用 Rust 原生目录遍历、系统文件元数据和受控子进程；完整文件盘点的折叠目录仍使用系统 `du`。引用检查不再依赖 Python 调用 `find`。界面先绘制 loading，再启动后台扫描；发现工作目录后可先显示预览，完整检查结束前禁用清理。进入页面和刷新都会重新扫描。

复用产物测量结果统计项目占用，避免重复深度遍历，并保留硬链接去重、共享块计算和执行前复核。缓存标记不存在时先做廉价的元数据检查；标记存在时继续完整的路径与身份校验，减少在普通目录上重复检查祖先路径。当前采用单个后台扫描任务；旧 Python 版本的 `CLEAN_MY_AGENT_SCAN_WORKERS` 设置在 Rust 版不生效。

2026-11-10，macOS Apple Silicon，4 个临时 Git 项目、80,000 个文件，包含跨源码 / 产物硬链接和外部符号链接。每个实现预热一次，再交错执行 3 轮；Rust 使用 release 优化构建，Python 使用迁移开始时的源码快照。计时包含程序启动、Git 检查、遍历和 JSON 输出；进程检查使用双方相同的隔离固定结果。

| 实现 | 完整报告中位耗时 | 三轮耗时（秒） |
| --- | ---: | --- |
| Python 迁移基线 | 1.0711 秒 | 1.0911 / 1.0711 / 1.0305 |
| Rust 0.4.0 | 0.8480 秒 | 1.1581 / 0.8480 / 0.8440 |

忽略采集时间后报告一致，双方无扫描错误。最终构建复测中，该样本耗时减少约 **21%**；首轮测得约 28%，复测存在运行波动。这是暖缓存、受控进程检查的结果，不代表真实主目录或冷磁盘上的固定倍数。

```sh
cargo build --release --locked
.venv/bin/python dev/rust-benchmark.py --binary target/release/clean-my-agent
```

对照脚本需要 `build/rust-migration/python-baseline/clean_my_agent/` 中的迁移基线；只在临时目录生成样本，不清理实际 Agent 数据。

## Python 0.3.2 历史优化

以下记录仅描述迁移前的 Python 实现，保留用于对照。缓存、`find` 批处理和并发环境变量不描述当前 Rust 实现。

- 同一次报告中，深度测量产物时同时收集占用摘要，统计工作树时跳过这些已测子树。保留跨产物、源码和目录内部的硬链接去重；稀疏文件按实际分配块计算，链接不跟随。
- 交互模式的引用检查也使用每批最多 64 个工作树的 `find`，保留 NUL 分隔的文件名和实际完成数量。
- 多 Agent 报告共用一次会话活动索引读取；测量结束后的引用复核和运行状态检查继续执行。
- 首页与子页面之间复用本次运行的完整报告，显示采集时间，手动刷新或执行操作后失效。缓存不写磁盘，不根据顶层目录修改时间推断所有后代都未变化。
- 清理执行前重新盘点，最终移动前继续执行原有策略、引用、安装证据和进程检查。历史快照保持只读。

macOS / Linux 支持 1–4 路受控并发，进度回调集中回到调用线程。默认 1 路：本机实测多路扫描的完整耗时更长，因此没有默认开启。较慢的存储可自行比较：

```sh
CLEAN_MY_AGENT_SCAN_WORKERS=2 clean-my-agent deps
```

省略该变量即恢复默认；不需要安装新的扫描工具。Windows 继续使用现有只读扫描后端，交互页面同样先列目录。

## 可复现对比

2026-11-10 在本机 macOS、Python 3.11 上，用 8 个生成的项目、80,000 个小文件测试，包含跨源码 / 产物的硬链接及外部符号链接。每个版本先预热一次，再交错运行 5 轮，取中位数。进程检查使用相同的固定结果，以隔离文件扫描成本；样本不包含真实 Git 历史或用户会话。

| 版本 | 完整报告 | 列表数据准备完成 |
| --- | ---: | ---: |
| 优化前 | 0.8356 秒 | 0.8356 秒 |
| 优化后，1 路（默认） | 0.7597 秒 | 0.0015 秒 |
| 优化后，2 路 | 1.0990 秒 | 0.0019 秒 |
| 优化后，4 路 | 1.2871 秒 | 0.0021 秒 |

上述结果在回归测试结束后单独采集，默认配置的完整扫描耗时减少约 **9%**。忽略观测时间字段后，各配置的完整报告一致。列表时间是后端提供目录数据的时间，**不含终端启动和绘制**；实际收益取决于目录结构、磁盘缓存、文件系统及运行状态检查，不能直接外推为真实主目录的耗时。

复现当前实现（只创建临时样本，不扫描用户主目录）：

```sh
.venv/bin/python dev/benchmark-scan.py --projects 8 --files 10000 --runs 5
```

对比旧实现时添加 `--baseline /绝对路径/旧源码`，该目录须包含 `clean_my_agent/`。脚本会检查报告一致性，不一致时以失败退出。

当前继续使用系统原生接口和 `du` / `find`。第三方并行扫描器可作为后续对照，但需要先验证分配块、硬链接、共享空间及链接处理口径；本次未新增该依赖。
