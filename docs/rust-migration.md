# Rust 迁移记录

目标：将 CLI、扫描、终端界面、文件操作、MCP 和发布流程迁移到 Rust。已完成本机验收并切换到 Rust 0.4.0。Python 实现保留作为兼容性对照，Rust 可执行程序独立运行。

## 验收范围

| 阶段 | 范围 | 当前状态 |
| --- | --- | --- |
| 1 | 只读扫描、策略、项目产物、活动信息、会话、资源、扩展、JSON 对照与性能 | 已完成，15 组对照通过；80,000 文件性能对比通过 |
| 2 | 总览、工作树、产物、会话、资源、暂存区、详情、搜索、多选、loading、取消和刷新 | 已迁移，真实终端检查通过 |
| 3 | 文件/目录暂存、恢复、永久清除、Git 工作树删除、独立仓库废纸篓、Codex 会话操作 | 已迁移，隔离测试通过 |
| 4 | MCP、HTML 报告、安装器、macOS/Linux/Windows 构建、实际程序验收与切换 | 已完成构建与本机切换；Windows 原生运行留待发布 CI |

保留现有 CLI 参数与 JSON 字段、保护路径规则、部分失败语义和旧暂存批次恢复能力。Windows 保持只读。MCP 不增加永久删除权限。

## 迁移约束

- 复用生成的小猫动画素材，不在 Rust 程序运行时依赖 Python。
- 分配量、硬链接去重、APFS 共享块及释放区间按现有口径验证；不以文件逻辑大小替代分配量。
- 扫描、引用检查、进程状态不完整时不开放清理；执行前再次核验策略、文件身份和目录内容。
- 文件操作保持路径范围、链接、挂载卷、并发变更、恢复冲突与操作锁保护。
- 使用临时目录验证变更操作，不以用户实际文件做删除测试。
- 区分源码测试、打包程序验证和本机已安装程序验证，记录实际切换结果。

## 对照基线

迁移开始时的 Python 源码和测试已快照到被 Git 忽略的 `build/rust-migration/python-baseline`。现有 185 项 Python 回归场景作为行为基线，新增 Rust 测试与跨实现比较脚本。

## 发布前本机验证记录（2026-11-10）

2026-11-10：首批 15 组端到端 JSON 对照全部通过，仅去除采集时刻；覆盖空目录、会话阈值、项目产物、外部工作树引用、资源、扩展、完整与快速扫描。对照脚本为 `dev/rust-parity.py`，结果位于 `build/rust-migration/parity/`（不入库）。

首批 22 项 Rust 单元测试通过，覆盖分配量、共享释放区间、跨产物硬链接去重、链接隔离、路径规范化、取消与子进程超时、重复配置项、标题控制字符以及 SQLite 不创建日志文件。正式优化构建已通过同一组 JSON 对照。

后续验证：31 项 Rust 单元测试、2 项 Rust 集成测试、18 项 CLI / MCP / 变更回归测试通过。集成测试覆盖 Git 工作树删除、状态变化时保留、Codex 原生命令结果确认、失败后停止后续会话。macOS 废纸篓通过真实系统 API 移动临时仓库并恢复，原有 Git 内容保留。

真实 PTY 验证了首次 loading、工作目录 loading、搜索、会话与分布、扫描取消、错误确认词不执行、暂存、恢复和永久清除。全部变更测试使用临时 HOME / 临时仓库，未清理用户真实 Agent 数据。

Rust MCP 使用官方 rmcp SDK，默认 8 个只读工具；显式 --allow-stage 开放 4 个可恢复操作，不提供永久删除工具。已验证协议握手、参数边界、工具权限与暂存恢复。

Windows 新增硬链接去重、junction 隔离、稀疏文件分配量和长路径测试，交叉检查通过；实际 Windows 运行由发布矩阵执行，该阶段未触发远端构建。GitHub 发布矩阵已改为在五个原生目标环境执行 Cargo 构建、测试和安装验证；该阶段没有发布 Release。

80,000 个文件的受控对照，完整报告中位耗时最终构建复测由 Python 1.0711 秒降至 Rust 0.8480 秒，减少约 21%；报告一致。测试口径和限制见 [扫描性能](scan-performance.md)。当前 Rust 采用单个后台扫描任务，旧 Python 并发环境变量不再生效；页面导航重新扫描，未复用旧实现的跨页面内存缓存。

`--build-info` 记录源码 SHA-256、编译器和目标平台，避免源码与安装版本混淆。构建辅助脚本与跨实现回归仍使用 Python，交付的 CLI/TUI/MCP 运行时不依赖 Python。Python 源码暂留作对照，保留迁移前已有工作区修改。

## 本机切换结果

2026-11-10，通过原安装器将 `~/.local/bin/clean-my-agent` 从 Python 0.3.2 更新为 Rust 0.4.0。新 shell 的默认命令路径、安装程序与构建产物的字节摘要、`--build-info` 和当前源码摘要均已核对。安装后再次通过发布冒烟、18 项 CLI/MCP 回归，以及真实终端的 loading、导航、暂存、恢复、永久清除流程。

- 原程序备份：`~/.local/share/clean-my-agent/backups/clean-my-agent-0.3.2-62ca8dfa932d`。
- Rust 源码摘要：`4ee9166e03bc8451e2ff954105de4574026fa9f850f275d65d45b89546015452`。
- 安装程序 SHA-256：`aba1c7a06501d42f69893a0fcebf34a20c14996e322e88447bd222fec5cb0768`。
- 本地安装包：`dist/clean-my-agent-v0.4.0-macos-arm64.tar.gz`；附带 SHA-256 文件。
- 检查日志、安装元数据：`build/rust-migration/validation/`（不入库）。

重复打包发现 macOS 对原地覆盖的可执行文件保留旧签名缓存，因此打包器改为新文件原子替换；连续两次打包与执行检查通过。既有安装器也使用原子替换。未修改 Agent 数据、现有 MCP 注册或发布远端版本。

真实目录复核发现查找阶段需遍历约 159 万个条目。针对不存在的 CACHEDIR.TAG，先做不授权任何写操作的元数据检查，存在标记时继续执行原有完整路径、链接、大小与身份检查；新增 2 项回归验证真实标记、错误标记、超大文件、标记链接及父目录链接。最终 macOS 为 33 项单元测试加 2 项集成测试。

真实 Codex 目录只读终端检查已发现 26 个工作目录，loading 在首屏出现。本次列表发现用时约 41.5 秒；此前版本的单次观测为 73.4 秒，实际目录检查不是受控性能基准。最初的完整快速 JSON 检查曾超过 120 秒的外部测试窗口，不能据此声称真实完整盘点已完成或套用合成样本加速比例。完整容量和清理资格仍需继续后台测量。
